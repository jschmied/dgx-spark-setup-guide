Picking an NVFP4 quant for an agentic coding agent on DGX Spark

Four ways to serve Qwen3.6-35B-A3B NVFP4 on a single GB10 — two weight sets × two MoE kernels. They are not interchangeable for a coding agent. Here's what actually differs, measured on SWE-bench.

GB10 · sm_121 · 128 GB unified vLLM 0.24 · CUDA 13 SWE-bench Verified + Multilingual temp 0.6 · MTP-3

Bottom line

Best overall
Unsloth · b12x — fastest path that doesn't collapse on Java/JS. 34/58 resolved, no calibration skew, native FP4 speed.
If NVIDIA weights
Use marlin, not b12x. Same speed, ~half the Java/JS give-ups. b12x's uniform FP4 activations are what break NVIDIA on Java/JS.
Python-only agent
Either NVIDIA config is fine — a slim edge over Unsloth (19 vs 17 / 30). The gap only opens up on other languages.
Always
Send temperature 0.6, and verify the kernel — b12x is not the default and will silently fall back to marlin.

D · NVIDIA·b12x 1910 11 Wins Python, folds on Java/JS

The give-up column is the whole story: on Java/JS, NVIDIA·b12x emits an empty patch 39% of the time — the agent flails and produces nothing. The same NVIDIA weights on marlin do it only ~10%. It's not the model or the checkpoint — it's the runtime FP4 activation quantization.

why

Activation precision

Give-ups track how hard the expert activations are quantized. 16-bit (marlin) or dynamic + FP8-carveout (Unsloth) hold up; uniform FP4 on all 40 layers (NVIDIA·b12x) collapses on non-Python.

why

Calibration

NVIDIA's modelopt scales are static, calibrated on English news (cnn_dailymail — no code). Unsloth is data-free / dynamic — computed per input, so it can't be domain-skewed toward Python.

watch

Don't trust Lite

SWE-bench Lite is 100% Python. On it NVIDIA looked far ahead (59 vs 38). That verdict does not survive contact with Java/JS. Benchmark the languages you'll actually run.

Prefill and decode are within ~3–7% — no widening gap. "marlin is too slow for agents" is a myth: at long context the prefill is attention-dominated (same kernel for both). What actually happened in agentic runs is subtler:

insight

Persistence ≠ slowness

marlin's longer wall-time on hard tasks is because it keeps trying (3 give-ups). b12x looks "fast" partly because it quits early (11 give-ups). Give a persistent config a longer per-step timeout.

note

The real cost is prefill

A 32k-token turn spends ~95 s before the first token — on both kernels. That's a GB10 property, not a kernel choice. Big tool observations (large Java files) are the tax.

note

b12x's real edge

Single-stream they tie. b12x's advantage is ~5% at concurrency (c≥4). It's a throughput lever, not a latency one.

The decisions

Choosing, in order

01

Language mix

Polyglot / any Java·JS·TS → weights that don't collapse (Unsloth, or NVIDIA on marlin). Pure Python → NVIDIA's slim edge is real but marginal.

02

Weights

Unsloth is the safe default — dynamic activations, no calibration to skew, no language hole. NVIDIA is competitive only on marlin.

03

Kernel

For Unsloth → b12x (that's what its FP4 design is for; needs a 1-line FP8-tail shim). For NVIDIA → marlin (b12x is the give-up trap). Speed is ~a wash either way.

04

Sampling

temp 0.6 coding preset. The generation-config default of 1.0 breaks tool-calling (1/8 vs 7/8 tool calls at low temp).

05

Serving stack

b12x needs CUDA 13 + cutlass-dsl 4.5.2. On 0.24 that's a manual pin; 0.25 upstreams it. Then opt in explicitly and run the preflight.

06

Timeout

A config that doesn't give up will take more turns on hard tasks. Set a generous per-step request timeout so persistence isn't misread as a hang.

Bad-by-default

Traps that make a good model look bad

Each of these silently degrades the out-of-box experience — you get a worse model and don't know it.

kernel

b12x is not the default on Spark. vLLM auto-select picks marlin on sm_121; you must pass --moe-backend flashinfer_b12x + CUTE_DSL_ARCH=sm_121a. A naive head-to-head is secretly marlin-vs-marlin — run the b12x preflight to be sure.

quality

NVIDIA·b12x's Java/JS collapse is invisible on Python. Static English-news calibration + uniform FP4 activations produce a 39% give-up rate that a Python-only eval never surfaces.

tools

The default temperature breaks agents. generation_config ships temp 1.0; tool-calling reliability craters. Override to 0.6 server-side or per-request.

ceiling

BF16 won't serve here. The 65 GB hybrid+multimodal model OOMs vLLM at KV/mamba profiling on 128 GB unified. On this box the practical ceiling is Q8, not BF16 — don't plan around a full-precision reference.

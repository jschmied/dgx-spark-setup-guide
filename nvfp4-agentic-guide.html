Picking an NVFP4 quant for an agentic coding agent on DGX Spark

Four ways to serve Qwen3.6-35B-A3B NVFP4 on a single GB10 — two weight sets × two MoE kernels. They are not interchangeable for a coding agent. Here's what actually differs, measured on SWE-bench.

GB10 · sm_121 · 128 GB unified vLLM 0.24 · CUDA 13 SWE-bench Verified + Multilingual temp 0.6 · MTP-3
corrected
2026-07-14

This page originally said NVIDIA·b12x "gives up" on 39% of Java/JS tasks. That was a benchmarking artifact, and the claim is withdrawn. Those empty patches were uncached Docker eval images timing out (pull_timeout = 120s) — the model was never called on those instances. The three configs ran back-to-back against a warming image cache, so the failures tracked run order, not the model: D ran first and lost 8 instances, C lost 2, A lost 0. Verified against the surviving harness reports: all 8 of D's failures are in its empty_patch_ids.

Scored only on instances each config actually attempted, real give-ups are ~3–4 for every config — no difference. What survives is a language split, and it is stronger than first reported. Numbers below are the corrected ones.

Bottom line

Polyglot agent
Unsloth · b12x — best on Java/JS (65% vs NVIDIA's 50%), native FP4 speed, nothing to mis-calibrate. The safe default.
Python-heavy agent
NVIDIA — its Python edge is real and bigger than we first thought: 73% vs 59% resolved. Kernel barely matters; marlin is the no-opt-in choice.
Kernel
Speed is a wash (within 3–7%, measured). There is no b12x "give-up trap" — that was the artifact. Pick b12x for Unsloth (its FP4 design), marlin otherwise.
Always
Send temperature 0.6, verify the kernel (b12x is not the default and silently falls back to marlin), and pre-pull your eval images before scoring anything.

The real finding is a language split, not a collapse: NVIDIA is clearly better on Python (73% vs 59%), Unsloth clearly better on Java/JS (65% vs 50%). Correcting the Docker artifact widened NVIDIA's Python lead — the old page called it "marginal". Every config gives up at the same low rate (~3–4/28), so there is no coverage story left to tell.

why

Calibration (hypothesis)

NVIDIA's modelopt scales are static, calibrated on English news (cnn_dailymail — no code). Unsloth is data-free / dynamic — computed per input, so it can't be domain-skewed. That predicts exactly this shape: strongest where the calibration is least wrong. Untested.

watch

Empty patch ≠ give-up

An uncached eval image blows the 120s pull_timeout and a slow model blows the 2h container_timeout — both produce an empty patch the harness scores as a failure. Always subtract grep -c "Error processing instance" before believing a give-up count.

watch

Don't trust Lite

SWE-bench Lite is 100% Python. On it NVIDIA looked far ahead (59 vs 38) — and on Python it is ahead. But that tells you nothing about Java/JS, where it loses. Benchmark the languages you'll actually run.

Prefill and decode are within ~3–7% — no widening gap. "marlin is too slow for agents" is a myth: at long context the prefill is attention-dominated (same kernel for both), so marlin's dequant-to-16-bit MoE barely shows.

withdrawn

The "persistence" story

This page used to explain marlin's longer agentic wall-time as persistence — "it keeps trying (3 give-ups); b12x quits early (11)". Withdrawn: the 3-vs-11 gap was the Docker artifact. b12x never quit early — 8 of its instances never started. With give-up rates equal, there may be nothing to explain.

note

The real cost is prefill

A 32k-token turn spends ~95 s before the first token — on both kernels. That's a GB10 property, not a kernel choice. Big tool observations (large Java files) are the tax.

note

b12x's real edge

Single-stream they tie. b12x's advantage is ~5% at concurrency (c≥4). It's a throughput lever, not a latency one.

The decisions

Choosing, in order

01

Language mix

This is the live variable. Polyglot / any Java·JS·TS → Unsloth (65% vs 50%). Predominantly Python → NVIDIA (73% vs 59%). Nothing else in this table matters as much.

02

Weights

Unsloth is the safe default: it wins the polyglot case and loses Python by less than the slice can resolve. Choose NVIDIA only if you know the workload is Python-heavy.

03

Kernel

For Unsloth → b12x (that's what its FP4 design is for; needs a 1-line FP8-tail shim). For NVIDIA → marlin, simply because it's the default and needs no opt-in — not because b12x is a trap. Speed is a wash.

04

Sampling

temp 0.6 coding preset. The generation-config default of 1.0 breaks tool-calling (1/8 vs 7/8 tool calls at low temp).

05

Serving stack

b12x needs CUDA 13 + cutlass-dsl 4.5.2. On 0.24 that's a manual pin; 0.25 upstreams it. Then opt in explicitly and run the preflight.

06

Benchmark hygiene

Pre-pull every eval image before a scored run, or raise pull_timeout / container_timeout. A cold Docker cache silently penalises whichever config runs first — and the damage looks exactly like the model giving up. It cost us a headline finding.

Bad-by-default

Traps that make a good model look bad

Each of these silently degrades the out-of-box experience — you get a worse model and don't know it.

kernel

b12x is not the default on Spark. vLLM auto-select picks marlin on sm_121; you must pass --moe-backend flashinfer_b12x + CUTE_DSL_ARCH=sm_121a. A naive head-to-head is secretly marlin-vs-marlin — run the b12x preflight to be sure.

quality

NVIDIA's Java/JS weakness is invisible on Python. It resolves 73% of Python but only 50% of Java/JS — a Python-only eval (like SWE-bench Lite) shows you its best face and hides the gap. Benchmark the languages you actually run.

bench

A cold Docker cache fabricates "give-ups". An uncached eval image blows mini-swe-agent's 120s pull_timeout; the instance is never attempted but is recorded as an empty patch and scored as a failure. This produced — and then destroyed — this page's original headline. Pre-pull images; subtract "Error processing instance" from any empty-patch count.

tools

The default temperature breaks agents. generation_config ships temp 1.0; tool-calling reliability craters. Override to 0.6 server-side or per-request.

ceiling

BF16 won't serve here. The 65 GB hybrid+multimodal model OOMs vLLM at KV/mamba profiling on 128 GB unified. On this box the practical ceiling is Q8, not BF16 — don't plan around a full-precision reference.

Method. One GB10 box, one agent scaffold (mini-swe-agent), patches scored by the official SWE-bench harness on x86.
